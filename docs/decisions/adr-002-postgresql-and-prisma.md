# ADR-002: PostgreSQL, Prisma ORM, and Custom Raw SQL Migrations

- **Status:** Accepted
- **Date:** 2026-11-02
- **Approval:** Owner Approved

## Context
QueueLess requires strong transactional consistency, strict data integrity constraints, range-based overlap prevention, and single-active-call invariant enforcement. The data model involves relational entities with foreign keys and multi-entity invariants.

We need a primary data persistence solution that provides type-safe query generation for rapid development while permitting advanced relational database features.

## Decision
QueueLess will use **PostgreSQL (v16+)** as the primary relational database, accessed via **Prisma ORM** for day-to-day schema modeling, migrations, and type-safe query execution.

To support advanced PostgreSQL features that the Prisma Schema DSL does not natively express, migrations will be managed using a **hybrid approach**:
1. Standard entity tables, foreign keys, and indexes are defined in `schema.prisma`.
2. Advanced engine constraints are created via custom raw SQL migrations (`npx prisma migrate dev --create-only`):
   - `CREATE EXTENSION IF NOT EXISTS btree_gist;`
   - `EXCLUDE USING gist (provider_id WITH =, tstzrange(start_time, end_time, '[)') WITH &&) WHERE (status != 'VOIDED')`
   - `CREATE UNIQUE INDEX single_active_call_per_session ON queue_tokens(queue_session_id) WHERE status IN ('CALLED', 'IN_SERVICE')`
   - `CHECK (start_time < end_time)` and `CHECK (duration_minutes > 0)`
   - Composite foreign key binding `Provider` to `OrganizationMembership` on `(user_id, organization_id, role)` with `role = 'PROVIDER'`.
   - Immutable audit trigger `trg_audit_events_immutable` raising SQLSTATE `P0001` (`raise_exception`) on `UPDATE` or `DELETE` (triggers protect against application bugs, but do not prevent modifications by database superusers or database owners).

## Alternatives Considered
- **TypeORM / Type-Safe Query Builders (Kysely / Knex)**: Kysely offers excellent SQL control, but Prisma provides superior schema declaration clarity, type inference, and built-in migration tooling.
- **Pure Raw SQL / pg-promise**: Provides full engine feature access, but requires substantial boilerplate for basic CRUD, schema type generation, and relational joins.
- **MongoDB / NoSQL Document Stores**: Rejected because appointment booking and live queue management rely fundamentally on relational integrity, ACID transactions, and engine-level range exclusion constraints.

## Consequences
- **Positive**: Type-safe TypeScript database queries; autogenerated client types; robust relational integrity guarantees; advanced PostgreSQL engine protections prevent race conditions that application code alone cannot catch.
- **Negative**: Prisma schema does not visualize raw exclusion constraints; developers must use `--create-only` raw SQL migrations when modifying advanced constraints; require PostgreSQL `btree_gist` extension in all environments.
